## 安装与入口

需要 **Chrome 145 或更新版本**；打包的 PDF.js 6 使用 `Map.getOrInsertComputed` 等浏览器能力。Overleaf 独立应用窗口由 Chrome 承载，应使用该应用对应的 Chrome 用户配置。

1. 构建本项目，或使用已构建的 `dist` 文件夹。
2. 在同一 Chrome 配置中打开 `chrome://extensions`，启用开发者模式，加载已解压的 `dist`。
3. 刷新 Overleaf 项目页或独立应用窗口，打开原有 **Settings → Extension**，展开后选择 **LaTeX Preview / LaTeX 预览** 或 **Codex Assistant**。

扩展更新或重新加载后，已打开的项目页仍需刷新。真正的 `Extension context invalidated` 会停止旧任务，并在原生 AI assistant 下方显示细线刷新图标；悬停或键盘聚焦时说明用途，不会自动刷新页面。Chrome 扩展管理页的 `Service Worker（无效）` 通常只是空闲后台休眠，不会因此移除扩展入口；短暂断线后，模型与历史读取可重连重试。提问和新建／切换对话不会在结果不明确时自动重发。Overleaf 重建页面 body 后，设置和侧栏入口会重新挂载，并恢复主题。

Extension 的选项、说明、按钮和扩展状态支持中英文，自动跟随 Overleaf 的界面语言；不使用浏览器语言覆盖网站选择。02 头像保留在 Extension 左侧。网站切换语言会导航至对应语言站，已保存的项目设置仍适用于同一项目。

如果光标已进入公式却没有预览，可在 **Settings → Extension → LaTeX Preview** 的项目支持区域点击绿色 **Reconnect editor / 重新连接编辑器**。它重新接入当前编辑器并确认连接恢复，不重新读取项目文件，也不修改文稿、光标或撤销记录；成功和失败会在按钮下方显示。返回编辑器时也会轻量检查并尝试恢复丢失的接入，不在每次输入时重连。这个按钮修复的是编辑器接入；扩展本身更新后的旧页面仍须刷新。

Extension 父项只展开或收起两个子项，原有预览设置完整保留在 LaTeX Preview 中。项目设置沿用原生布局；只有 API 连接和密钥管理使用独立的扩展设置页。Codex Assistant 的入口位于左侧栏原生 AI assistant 下方，打开后显示聊天面板。补全仍加入原列表。预览由扩展完整管理，沿公式位置显示，开启增强预览时隐藏原生浮窗；不再依赖原生 Equation preview 开关或结果。补全来源文字使用 Overleaf 界面字体，以小号浅灰色在行内居中显示；过长路径省略，悬停可查看完整路径。补全需要原生 Auto-complete 开启，由你选择后才插入正文，可正常撤销。

本机 TeX 还需要配套 Native Messaging 连接程序和系统 TeX Live；单独加载扩展不会安装它们。安装、卸载与运行限制见 [本机连接说明](docs/native-backend.md)。MathJax 和云端模式不需要本机连接程序。

## Codex Assistant

Codex Assistant 默认使用本机 Codex 的现有登录，通过单独的 Native Messaging 连接程序与扩展通信。Native Messaging 是 Chrome 启动本机程序并通过标准输入/输出交换消息的机制；这里不启动 localhost 服务。默认 Codex 模式需要本机可用且已登录的 Codex App 或 CLI，模型和使用额度沿用本机 Codex 配置。Windows 安装命令见上方开发版说明；下面的 `/usr/bin/python3` 命令用于 macOS。0.10.0 也支持自备 DeepSeek 或其他兼容 OpenAI Chat Completions 的 API；此模式仍需安装连接程序，但不需要 Codex 登录，按所选 API 服务的用量计费。

在本项目根目录执行独立安装命令：

```sh
/usr/bin/python3 native/install_codex.py --install
```

上面不带工作区的命令适合更新已有绑定或只使用 API。首次需要为新 Codex 聊天配置已有 Overleaf 项目的工作目录和 app-server 项目 ID 时，应加 `--workspace /absolute/path/to/Overleaf`（Windows 的完整命令与配置审计见 [安装说明](docs/windows-development.md)）。没有现有 `workspace.json` 时，单独 `--install` 会使用 helper 的私有数据目录。app-server 绑定与 Desktop 侧栏分类是独立记录；即使新线程的工作目录和 backend 项目 ID 正确，新旧聊天仍可能需要在 Desktop 使用 Move / 移动到项目操作归入 Overleaf。补配置不自动迁移旧聊天，扩展不直接改写 Desktop 全局状态或聊天库。

它注册 `com.overleaf.personal_tools.codex`，与公式预览的 TeX 连接程序分别安装、分别更新。只运行扩展构建或旧的 `native/install.py` 不会安装 Codex 连接程序。安装后重新加载扩展、刷新 Overleaf，打开 **Settings → Extension → Codex Assistant** 即自动读取登录状态、可用模型和各模型支持的推理强度；此操作不发送提问。加载时显示进度，失败时可点击 **重试连接 / Retry connection**，也可用 **检查连接 / Check connection** 主动刷新。成功结果在当前页面保留五分钟；若正在生成回答，检查延后到回答结束，避免打断。完整安装、卸载及运行说明见 [Codex 本机连接](docs/codex-backend.md)。

**升级到 0.11.2** 时重新运行上述安装命令，以一起更新连接程序、Desktop 适配及 API 模块，然后保留未发送草稿、重新加载扩展并刷新 Overleaf。原有 Codex 设置和会话保留；没有选择 API 连接的项目继续使用 Codex。

0.12.0 需要同时更新扩展和本机连接程序。安装器会注册本机只读 `overleaf_project` MCP，使 Codex 能自行搜索和读取完整项目文本；已经打开的 Codex 桌面可能需要重启一次载入新连接。Settings → Extension → Codex Assistant → Messages while working 可选择排队（默认）或直接引导，设置自动按账号与项目保存；输入区保留统一发送操作，排队消息旁可点 Steer now 转为引导。不支持引导时自动排队。

0.11.1 只更新浏览器扩展，已安装的 0.11.0 本机连接程序不需要重装。Code / Visual 中主动取消选区后，输入框上方的文稿引用同步消失；移到输入框提问时仍保留。Visual 正文中未点击的自定义宏公式也使用项目宏补充渲染，保持原有点击编辑方式。

### 使用自己的 API

1. 打开 **Settings → Extension → Codex Assistant → Manage API connections / 管理 API 连接**，进入扩展自己的设置页。
2. 新建连接，填写名称、API base URL、模型 ID 和 API key；可使用 DeepSeek 预设，再按自己的账号填写密钥和模型。保存后可点 **Check connection / 检查连接**。
3. 返回 Overleaf 设置，刷新连接列表，在 **Model source / 模型来源** 选择该连接，最后保存项目设置。

支持保存多个连接，选择按 Overleaf 账号与项目分别保存。连接管理页只向本机程序提交密钥；密钥不会填入 Overleaf 页面或 Chrome storage。本机将其保存在权限受限的文件中（macOS 目录 `0700`、文件 `0600`；Windows 为当前用户和 SYSTEM 的受保护 ACL），不是系统加密凭据保险库。编辑已有连接时留空密钥会保留原值；更换服务地址需新建连接，避免把原会话发往另一个地址。删除连接会保留已有本地历史。

检查连接只向已保存的地址请求 `/models`，不发送问题或文稿。成功读取列表不等于已验证实际问答能力；空模型列表尤其不表示所填模型可用。Overleaf 设置中的 API 状态只确认本机保存的配置，实际服务检查在连接管理页进行。API 需支持 `/chat/completions` 的文本回答；支持流式或普通 JSON 响应。地址使用 HTTPS，本机服务可用 loopback HTTP。

API 模式沿用 Code／Visual 选区、项目上下文、回答引用、公式显示和复制功能。面板显示连接名称；项目模式通过兼容 API 的工具调用读取完整文本快照，要求服务商支持 function calling。聊天按 **API 连接、Overleaf 账号、项目** 分开保存在这台 Mac，既不混入 Codex 历史，也不在 Codex 桌面同步续聊，因此不显示“在 Codex 中打开”。切换来源不会把旧对话自动发送给新服务。服务失败不会自动切换到 Codex、另一个 API 或重发问题。停止会关闭本地请求，但远端可能已开始生成并计费。

0.10.0 的新增 API 路径使用合成数据和模拟服务进行自动化验证；本次没有浏览器实页验收，也没有向真实 API 发送验证问题。下列历史验收记录仅代表对应旧版本。

### 追加问题：排队与引导

回复生成时，输入框提供 **Queue / 排队**、**Steer now / 立即引导** 和独立的停止按钮。按 Enter 默认将追加问题排队，Shift+Enter 换行，不会把当前回复替换为新问题。

**排队**会在当前轮结束后按顺序发送。每项在加入时保存问题、文稿选区、回答引用、完整项目快照的引用和设置；之后编辑文稿不会悄悄改变已排队的问题。队列最多 8 项，总大小受 1 MiB 限制，并与当前 Overleaf 账号、项目、模型来源及对话绑定。有排队项时需先处理或移除它们，才能切换来源、新建或切换对话。可以移除未发送项，或在输入框没有草稿时将它移回编辑器；重新提交会重新收集当时的上下文。

账号可识别时，队列保存在此 Chrome 配置的本地存储中。刷新后恢复为暂停状态，点击 **Resume queue / 继续队列** 才继续；停止、连接失败或发送结果不明确也会暂停。可能已经发送的项目不会自动重发，需先查看对话，再编辑或移除该项。没有可识别账号时，队列只在当前页面保留。

**立即引导**用于给当前回复补充要求，仅在连接已确认支持时可用。独立 Codex 连接会核对正在生成的轮次；已接通的 Codex 桌面会话遵循桌面自己的当前回复规则，不另开一轮。自备 API 使用排队。没有可补充的回复或引导结果未确认时，保留输入供检查；不会通过“停止再重发”模拟引导，也不会自动转成排队。

### 文稿上下文与对话

DeepSeek 等 API 使用 **当前项目** 上下文时，可在 **Settings → Extension → Codex Assistant → API reading budget** 调整读取轮次（1–256，默认 64）、工具调用次数（1–512，默认 128）和总时限（90–580 秒，默认 580）。一轮可能包含多次项目检索；最终回答另有一次机会，并从总时限中预留 60 秒。提高预算可能增加 API 请求、Token 用量、费用和等待时间，这些上限并不代表每次都会用满。数值离开输入框后自动保存，仅影响之后发送的消息；正在处理及已排队的消息保持原设置。预算不足时尝试给出注明已读范围的阶段性回答。

**项目模式**会在发送、排队或引导时重新读取项目源文件，将当前活动编辑器的实时内容覆盖到该版本。源码分片传到本机专用目录，经文件字节数与 SHA-256 校验后发布不可变快照。模型通过只读工具列目录、搜索和分页读取全文；当前支持的文本源文件上限为 2,000 个、单文件 2 MiB、合计 16 MiB，图片和 PDF 不在此文本读取范围内。超限或不完整会阻止发送，不再把项目节选当作全文。选区模式仍只附选区和附近正文。

Codex 桌面续聊可使用同一快照引用和 `overleaf_project` MCP；读取的是上一次在 Overleaf 同步的版本。网页后续修改会在下一次发送／排队／引导时同步，关闭网页后不会自动抓取新修改。旧队列只有节选的项目消息需要取回编辑并重新捕获完整项目。源码保存在 `~/Library/Application Support/OverleafPersonalTools/codex-assistant/project-context`，聊天气泡保持简短。

在 **Code** 或 LaTeX **Visual** 编辑模式中选中内容，再点击左侧原生 AI assistant 下方的 **Codex Assistant**。输入框上方显示引用的文件、行号和原文；选区在转到聊天输入框后保留，可以手动移除。输入问题并发送后，引用保留在该条问题上，可展开完整原文；重新打开已保存的对话也能查看引用。回答会逐步显示，支持数学公式、停止生成、新建对话和调整面板宽度。思考状态显示在回答的 Codex 标签旁，侧栏入口和图标按钮提供悬停及键盘焦点提示。上滚查看前文时保留阅读位置，点击“回到最新回复”可恢复跟随。设置和按钮跟随 Overleaf 的中英文界面，字体与配色取自网站原生控件。

在单条 Codex 回答中选中一段内容，点击输入框上方出现的 **Quote selected text / 引用所选内容**，即可附到下一条问题。回答引用卡片可展开完整文字或移除；再次引用会替换当前回答引用，可以同时保留文稿选区。公式保留原始 LaTeX；选区端点落在公式中时引用整个公式。添加引用不会自动发送，也不改变系统剪贴板；输入问题后再发送。已发送的引用会随历史保存，刷新或重新打开会话后仍可查看。每段回答引用最多 64,000 个 UTF-16 单元，选区需要位于同一条回答内。

从 0.11.0 起，Overleaf 新发送给 Codex 的普通问题和“立即引导”消息，只在聊天正文中显示实际问题；选区、项目文件和回答引用仍作为独立上下文提供给模型，不再把整段技术包装塞进问题气泡。Codex 桌面中生成的已知回答注释格式，同步回 Overleaf 时显示为实际问题和可展开的引用卡。未识别或损坏的包装不会被猜测删除；较长用户消息默认折叠为约六行，可展开查看完整内容。这些调整不改写原始 Codex 会话或日志，旧的桌面消息不会被追溯修改。API 模式继续显示问题正文，同时保留其原有上下文发送方式。

**升级到 0.9.4** 时需重新运行上面的 Codex 连接程序安装命令；安装命令保留已配置的工作目录，旧会话历史自动兼容迁移。从 0.9.3 升级时，续聊修复只涉及本机连接程序：可在没有回复生成时，关闭 Codex Assistant 并保存，再开启、保存并检查连接，让现有网页连接新程序。此操作保留当前草稿和引用。完整扩展更新仍按通常方式重新加载扩展并刷新 Overleaf。

项目设置包括启用开关、模型来源、Codex 模型和推理强度、上下文范围、项目补充要求和 **Panel position / 面板位置**。可选左侧或右侧，也可用标题栏快捷按钮切换，位置随项目保存；右侧面板占据实际布局空间，可与左侧文件树同时使用。**Follow Codex / 沿用 Codex** 在独立连接时使用本机 Codex 配置的默认模型或推理强度；连接桌面持有的同一会话时沿用该会话当前的模型和推理强度；打开设置后即可加载其他可用模型。显式选择模型时，推理强度选项按本机返回的支持范围显示。模型加载和失败重试会保留尚未保存的设置。**当前项目**模式从已有文本快照中选取相关文件，并优先使用当前编辑器内容；**选区及附近**模式只提供引用选区及周边文本。发送前会显示或说明上下文读取问题；大项目受文件数与字符预算限制，可能省略文件或截取片段，并非每次发送全部资料。跨窗口或协作者修改的未打开文件仍需在 LaTeX Preview 中 **当前项目支持情况右侧的“重新读取命令与宏包”**。

点击标题栏的时钟进入 **Conversation history / 对话历史**，查看当前模型来源、此 Overleaf 账号和此网页项目下历次新建的对话。列表显示标题、更新时间和当前标记，支持分页；选中后可继续提问，也可重读当前对话恢复加载。聊天顶部的 **Load earlier messages / 加载更早的消息** 按页补齐旧记录并保持阅读位置。**New conversation / 新建对话** 开始一个新会话，旧会话仍留在历史中。使用 Codex 来源时，**Open in Codex / 在 Codex 中打开** 可将所选会话交给桌面应用打开。

使用 Codex 来源时，同一条已登记会话在 Codex 桌面续聊后，Overleaf 会读取新增问题和回答：面板可见时每五秒检查一次，返回标签页或重新打开面板时立即检查。更新保留草稿、引用、阅读位置和已经加载的旧消息。发送前再次核对最新上下文；两端共享同一个线程 ID，不复制或分叉聊天。**0.9.4 支持向当前桌面会话直接发送**：桌面持有会话时，通过本机 Desktop 的 owner/follower 通道把问题交给它，沿用同一个聊天 ID；不再要求空闲桌面释放会话或重启。回答流和停止操作也指向同一轮。若桌面正在回答，可将追加问题排队，待该轮结束后继续。此适配使用当前已验证的 Desktop 内部协议，连接前校验能力和版本；版本不兼容或发送结果未知时明确报错，不自动重发、抢锁或分叉。

从 Overleaf 发送问题时，当前选区、文件位置、附近文本、回答引用和设置范围内的项目文件仍随问题提供给同一条会话；桌面续聊可以继续使用这些上下文。网页中的新编辑会在下次从 Overleaf 提问时更新上下文。桌面单独发送问题并不会主动重新读取网页，未打开文件的快照刷新规则仍与上面相同。

引用卡片上的 **Go to source / 回到引用位置** 可返回文稿或原回答，待发送卡片和历史消息均支持。文稿引用会打开对应文件，在当前 Code／Visual 模式中选中原文；位置移动后会核对原文重新定位，文字已改动或匹配不唯一时提示。回答引用会定位并短暂高亮同一对话中的原回答，需要时加载较早记录；一次读取有上限，提示后可继续点击。跳转保留输入草稿和已附引用，不自动发送消息或改写正文。

每条 Codex 回答的 **Copy source / 复制原文** 按钮复制完整原始 Markdown，保留公式 LaTeX。公式没有浮动复制按钮。在 **Settings → Extension → Codex Assistant** 可启用默认关闭的 **Click formulas to copy LaTeX / 单击公式复制 LaTeX**，启用后单击完整公式即可复制不含定界符的 TeX，成功时保留短暂淡色反馈。独立的 **Show formula copied notice / 显示公式复制提示** 开关默认关闭；开启后还会短暂显示小型“公式已复制”提示，不抢输入焦点。普通文字选区跨过已渲染的公式时，公式也会显示选中高亮，Cmd/Ctrl+C 保留原公式源码。复制不修改正文或当前引用。

可为此扩展后续创建的 Codex 会话配置已有 app-server 项目及工作目录；网页的账号／项目隔离不变。Desktop 侧栏归类仍需单独核验，不能由以下安装命令保证。在 macOS 中指定已有 Codex 项目目录，例如：

```sh
/usr/bin/python3 native/install_codex.py --install --workspace "$HOME/Documents/Overleaf"
```

此路径是本机配置示例；连接程序会查找匹配的已有 Codex 项目，具体安装与历史存储说明见 [Codex 本机连接](docs/codex-backend.md)。

### 常见问题

- **需要 Git integration 吗？** 不需要。扩展使用当前登录的 Overleaf 项目和既有只读文本读取方式。切换项目后使用该项目的设置与对话；本版没有额外的全账号项目列表。
- **会自动改稿或执行命令吗？** 本版提供只读问答，不修改 Overleaf 文档，不执行回答里的命令。需要采用修改时，请自行检查并复制到编辑器。
- **是不是把桌面里当前的 Codex 对话放进来？** 默认来源使用本机 Codex 服务和登录，按 Overleaf 账号与网页项目维护各自的对话历史。可恢复此扩展已登记的旧会话，并在桌面打开；不会扫描或导入其他任意桌面对话，也不会自动导入桌面技能、记忆或插件。新建对话不会删除或归档旧会话。
- **Visual 和 PDF 选区有什么边界？** LaTeX Visual 会把文本选区映射回编辑器的真实 TeX，卡片显示源码及源码行号。需要两端属于同一编辑器；不能准确映射时不添加新引用。PDF、独立的 `.bib` 可视表单，以及渲染公式小组件内部任意子字符串不支持；若宿主已提供完整公式的源码选区，则可引用该源码。
- **切换 Codex 账号后原对话连接失败？** “已登录／能读取模型”与“当前桌面能接收此会话的问题”是两项检查。新版会刷新登录连接，并完整等待桌面的会话查找结果；如果原会话仍被其他写入端占用，却没有可访问的桌面会话，请在当前 Codex 窗口打开同一聊天后再试。仍不可用时可显式新建对话，原历史保留；扩展不会抢锁或自动复制旧对话。
- **安装后仍未连接？** Codex 模式先确认本机 Codex 能正常登录使用；API 模式先在连接管理页检查地址、模型和密钥。再重新执行上面的独立安装命令并刷新网页。连接程序更新后也需重新安装；只刷新网页不会更新已复制的本机文件。

## 项目与宏文件

- 始终分析主文件及其 `\input`、`\include`、项目内 `\usepackage` / `\RequirePackage` 依赖。
- **自动模式**：查找唯一的 `macros.sty`；文件名可改。没有则不额外加载，多份同名文件则提示选择。
- **手动模式**：展开紧凑的文件选择器，搜索并勾选项目内的额外宏文件；**不加载额外文件**只关闭额外添加，不移除项目本来加载的依赖。
- 默认自动沿用 Overleaf 的主文件设置，不需要重复指定。无法读取且存在多个文档入口时才显示候选选择；历史手动覆盖可在折叠的高级设置中取消。
- 设置修改后自动按项目保存，无需再次点击保存。“Set as defaults／设为默认”用于此浏览器中尚无独立设置的项目，已有项目设置保持不变；主文件、预览来源顺序与开关不带入默认值；共享云端项目绑定按账号单独保存。

初次读取通过同源 GET 下载项目 ZIP，在页面内存中保留文本快照。路径明确时，当前文件的编辑器内容覆盖快照。重命名、删除、其他窗口或协作者对未打开文件的修改，需要点击 **当前项目支持情况右侧的“重新读取命令与宏包”**。同名文件路径无法判定时，不猜测覆盖哪个文件。

## 预览模式

展开 **预览来源 / Preview sources** 可查看检测到的宏包和定义文件，逐项勾选是否参与预览，用上下箭头调整加载顺序。项目内的 `.sty` 只列一项，不会同时出现宏包和文件两个开关。新增来源默认启用；设置只影响预览，补全仍保留所有已读取的命令。

**恢复默认来源 / Reset preview sources** 清除来源开关和排序，保留额外文件的选择方式；点击保存后生效。

列表从上到下加载，后面的来源优先级更高。MathJax 对已适配来源的同名命令按该顺序处理；标准数学命令始终可用，关闭 `amsmath` 不会删除基础的 `\operatorname` 等能力。没有调整顺序时保留项目原有的交错加载顺序。TeX 保留真实的声明语义：若使用 `\newcommand` 重复声明已有命令，仍可能报错，需要在源文件中使用合适的定义方式。

自定义 TeX 来源开关和排序只改隔离预览工作区中的文本。可明确识别的静态 `\input`、`\usepackage` 和 `\RequirePackage` 链可以处理；无法安全改写的动态引用、条件加载或混有复杂正文的来源会明确报错，不会悄悄忽略开关。保持默认来源设置时继续使用原导言区。

| 模式 | 执行方式 | 范围与要求 |
| --- | --- | --- |
| MathJax | 浏览器内即时渲染 | 仅执行已适配数学命令和可解析自定义宏 |
| TeX → Overleaf | 所有项目共用一个轻量云端预览项目 | 真实 LaTeX 宏包；需要登录、网络和账号编译资源 |
| TeX → 本机 | Native Messaging 调用已安装的 TeX | 真实宏包；需要 macOS 沙盒、连接程序和兼容的 TeX 环境 |

TeX 模式生成新入口：保留主文件的完整导言区，按设置补入额外宏文件，仅放入当前公式，并用 `preview` 宏包裁切页面。它不编译原正文。文档边界必须能明确识别；动态生成 `\documentclass` 或 `\begin{document}` 等结构可能被拒绝。PDF 必须为单页，再由打包的 PDF.js 转成弹窗图像。

真实引擎可以执行 MathJax 未实现的宏包和复杂定义，但不会重现原文档的全部状态。正文中定义的命令、标签、交叉引用、计数器、页码、辅助文件和 `\jobname` 可能不同；依赖外部工具、shell escape 或特殊构建流程的宏包也可能失败。导言区自身包含正文钩子或复杂输出例程时，单公式裁切可能不适用。

### Overleaf 云端

首次在 Extension → LaTeX Preview 中启用共享云端预览项目。扩展创建一个空白的 **Overleaf Personal Tools — Preview** 项目；以后同一 Chrome 用户配置、同一 Overleaf 账号的各项目和中英文站都复用它。重复点击启用会连接已有绑定，不复制当前论文，也不按论文新建项目。不同设备或 Chrome 用户配置之间暂不自动同步绑定。

每次预览保留当前主文件的导言区，只加入当前公式，并按需收集项目内的 `.sty`、`.cls`、`.tex` 等文本依赖和指定额外文件。标准宏包由 Overleaf 已安装的 TeX Live 提供。原主文档正文、无关章节和未引用的 bibliography 不上传到共享项目。源项目读取仍使用前述 ZIP 快照，不能把“按需上传”理解成已经实现逐文件网络读取。

文件内容相同便跳过上传；切换项目或依赖后，会清理扩展登记的过时文件并覆盖变化的文件，避免两个项目的同名 `macros.sty` 混用。同步、编译和下载 PDF 共用账号级队列，一次只有一个标签页操作共享项目。共享项目只供扩展管理；检测到未登记文件或文件身份变化时会停止同步，不把未知内容自动当作可删除文件。不要在其中手动写论文或添加文件。

云端编译器和 TeX Live 版本从原项目元数据读取，并在需要时同步到共享项目；原项目设置保持不变。元数据短期缓存 15 秒，当前页面原生编译器/版本变化会使缓存失效；读取不到明确环境时报告原因，不猜测。不同项目需要不同环境时会在队列内切换，仍不能保证原正文状态或外部工具完整复现。

输入时保留 MathJax 即时草稿，停顿 650 毫秒后再安排 TeX。等待期间已过时的公式会取消排队；已发出的远端编译可能继续运行，但不会显示到新公式上。账号级编译间隔至少 3 秒，发生请求错误后通常退避 10 秒；这与网络和真实编译耗时共同决定结果出现时间。页面内另缓存最多 12 份、合计不超过 16 MiB 的 TeX PDF，命中相同公式、依赖和环境时复用结果。

共享项目中的预览文件会保留，也会消耗账号编译资源；删除过时文件不表示 Overleaf 历史中的旧内容一定消失。旧版本创建的逐项目副本保留，不自动迁移或删除。当前轻量模式仅同步文本，项目图片、字体二进制和不能静态确认的动态依赖仍有限制。

云端接口来自 Overleaf 内部实现，并非稳定插件 API。创建结果不明确时不会自动再建一个项目；任务失联时会暂时隔离共享工作区，避免旧编译与新上传重叠。具体流程、等待行为、数据保留和维护方法见 [共享云端预览方案](docs/shared-cloud-preview.md)。0.7.0 已完成真实网站上的创建、重复连接、公式编译、缓存重入和中英文站跨项目复用检查；并发与异常恢复的验证范围见 [验收记录](docs/overleaf-evidence.md#shared-workspace-acceptance-2026-10-30-070)。

### 本机 TeX

选择 pdfLaTeX、XeLaTeX 或 LuaLaTeX，再用 **检查本机连接** 查看可用性。连接程序使用 Python 标准库，通过 Chrome Native Messaging 的标准输入/输出通信，不启动 localhost 服务。

每次任务只把公式预览需要的项目文本写入独立临时目录，在 macOS 沙盒中调用已识别的系统 TeX Live。允许读取对应 TeX 安装和系统字体等必要依赖；不复制项目图片或字体二进制文件，也不使用个人 TeX 配置目录。需要这些项目资源的公式可能无法编译。沙盒不可用时不会退回无沙盒运行。

新请求、取消或关闭页面会断开对应任务连接，连接程序据此终止 TeX 子进程。任务完成或失败后清理临时目录。编译时间、输出和进程资源有限额，详见本机说明。

## 自动补全与 MathJax 支持

| 来源 | 当前能力 |
| --- | --- |
| physics | 常用导数、定界符、向量、bra-ket、矩阵、算符及参数模板，按声明启用 |
| amsmath / amsfonts / amssymb | 常用补全目录与 MathJax 数学支持 |
| mathtools / braket / cancel | 命令目录与相应 MathJax 适配 |
| bm | 补全；MathJax 使用 boldsymbol，精确字体以 TeX 为准 |
| 自定义宏 | newcommand / renewcommand / providecommand / DeclareMathOperator、简单 def/let、可准确表示的 xparse 子集 |
| 数学字体声明 | `DeclareMathAlphabet` 的 `OML/cmm/b/it` 映射为粗斜体；其他字体声明明确提示使用 TeX |
| 其他宏包 | 识别声明、分析项目内源码，未适配部分显示诊断 |

**切换到 TeX 不会自动枚举任意宏包的所有命令。** 补全仍来自维护的命令目录与可解析定义；完整 TeX 扩展的是预览执行能力。

MathJax 使用自己的数学字体。即使命令可以生成 SVG，`mathrsfs` 等外部字体的具体字形也可能不同；需要与编译 PDF 的字形一致时请使用 TeX。

MathJax 支持公式中的 `\ensuremath`，包括自定义宏内的嵌套调用；它不完整执行 TikZ、任意条件/展开程序、自定义字体、复杂 xparse 或任意 `.sty`。physics 不支持的选项及 `\qty` 等命名冲突会提示；未知或不支持的公式不显示猜测性替代。默认项目自定义宏优先于适配目录；明确调整来源顺序后按新顺序处理已适配命令，但复杂 TeX 作用域不由解析器完整模拟。

公式范围沿用 Overleaf 原生识别。用 `\be` / `\ee` 等宏隐藏数学环境时，可能无法触发弹窗。Code 和 LaTeX Visual 模式共用同一套预览：在 Visual 中点入公式并编辑其源码时显示，退出后保留 Overleaf 原生的行内公式展示。语法解析稍后完成、公式组件展开以及模式切换都会更新当前公式与位置；仅移动位置不会重新渲染或重启 TeX 等待。公式组件内部的原生静态渲染不由扩展替换。

## 数据、权限与限制

权限为 `storage` 和 `nativeMessaging`。内容脚本仅匹配 www.overleaf.com 与 cn.overleaf.com 的项目页面；云端请求使用当前 Overleaf 会话及页面 CSRF 令牌，目标限定在 Overleaf 同域。不读取或保存账号密码，不发送遥测，不从 CDN 加载运行代码。

预览的源码快照和渲染缓存留在页面内存；Chrome storage 保存设置、账号 → 共享预览项目绑定、文件身份与内容摘要，以及队列/租约期限，不持久保存预览用的正文、公式文本或 PDF。账号来自 Overleaf 页面提供的用户 ID，不使用邮箱作标识。云端预览在共享预览项目中持久保存同步文本和生成入口；本机 TeX 将文本交给连接程序，在临时目录处理，不另行上传给第三方服务。

使用 Codex 来源时，Codex Assistant 在本机按 Overleaf 账号和网页项目保存已登记会话的问答历史，并从 Codex 的线程记录补齐旧内容；历史列表与聊天内容均按页读取，不受浏览器最近记录条数限制。此 Chrome 配置的本地存储另保存项目设置、面板位置与有限的显示缓存，最多保留最近 60 条、合计 350000 字符（包括文稿选区和回答引用）；记录包含问题、回答、发送时引用的文件／行号／原文，以及选中的回答片段。按问答组保留最近记录；若最新回答本身超过保存预算，会完整保留问题及两种引用，并明确标记回答为历史节选，避免清空整个面板记录。当前页面的完整回答不因此截断。仅在发送问题时，把问题、项目补充要求和所选上下文交给本机 Codex，再由其已配置的服务处理。Codex 按自身正常对话机制保存历史和提供的上下文；“本机连接”不表示模型离线运行。账号可识别时，本机按账号与网页项目保存会话目录、消息及当前对话绑定；账号不可识别时不跨连接恢复绑定。详细存储位置和边界见 [Codex 本机连接](docs/codex-backend.md)。

选择自备 API 后，问题及相同范围的文稿上下文由本机程序直接发送至所选 API 地址，受该服务的数据保留和使用条款约束。连接元数据和密钥位于本机私有 `api-connections/profiles.json`；Chrome storage 保存来源选择、该来源独立的显示缓存，以及下述由用户明确加入的待发送队列。API 本地历史按连接、账号和项目隔离，保留问题、回答、引用及续聊所需上下文，不向 Codex 导入。删除 API 连接或卸载扩展不会自动清除这些历史；详情见 [API 连接与存储](docs/codex-backend.md#optional-api-connections-0100)。本版没有新增 Chrome 权限。

聊天显示变短不表示模型收到的上下文变少：新 Codex 请求仍提供完整的有界选区、项目文件和回答引用，只把它们与可见问题分开传送。同步时提取的注释引用仅改变 Overleaf 显示，原始 Codex 记录保留。普通长消息展开后仍可查看全文；不能确认格式的消息不会按标题关键词擅自裁掉内容。

待发送队列另以最多 8 项、总计 1 MiB 的预算保存在 Chrome 本地存储中，包含加入时捕获的问题、选区、回答引用、项目文本和设置。它与显示历史分别保存，不使用 Chrome Sync；完成或移除会删除对应队列项。刷新后不会自动发送；只有继续队列或明确重新提交后才会把保留的上下文交给所选服务。正在发送时发生断线的条目会标为需要检查，不自动重放。账号不可识别时不持久保存队列。

项目读取上限为 32 MiB 压缩 ZIP、2 MiB 单个文本、16 MiB 总文本和 2000 个源文件。TeX 打包另限制为 200 个源文本、约 800 万字符及 32000 字符公式；各后端还有字节、时间和 PDF 限额。更严格的一层可能先触发，超限会报错。

## 开发与维护

需要 Node.js 22+ 和 pnpm；保留锁文件。常规检查包含 TypeScript、Vitest 和扩展构建：

```sh
pnpm install --frozen-lockfile
pnpm check
```

这台 Mac 可使用 `./dev.sh check`、`./dev.sh build`、`./dev.sh test`、`./dev.sh dev`。PATH 中没有 Node 时尝试已有 Codex runtime，不安装系统运行时。本机连接程序测试单独运行：

```sh
/usr/bin/python3 -m unittest discover -s native/tests -v
```

原生测试在具备沙盒和 TeX 时执行合成编译用例，其他环境跳过对应部分；Codex 连接程序测试使用模拟 app-server 检查协议、权限与取消流程；API 测试使用合成数据和模拟 HTTP 服务检查配置、隔离、响应及错误处理，不调用真实推理。普通 `pnpm check` 不安装或注册 native host，也不创建真实云端项目。

可以用显式文件路径复查自己的宏文件，报告默认写入不入库的 `artifacts/macro-audit/`，不上传文件：

```sh
node scripts/audit-macros.mjs /absolute/path/to/macros.sty
node scripts/audit-tex-macros.mjs --inventory artifacts/macro-audit/inventory.json
node scripts/smoke-preview-sources.mjs
```

审计逐项记录声明、代表调用、上下文和错误，区分环境别名、配置声明、被后续覆盖的定义及字体差异。一次代表调用成功不表示任意参数都正确，也不表示 MathJax 与 TeX 字形完全相同。

更新流程：构建 → Chrome 扩展管理中重新加载 → 刷新 Overleaf。TeX 与 Codex 连接程序更新时，分别运行对应安装脚本重新注册。关闭或卸载扩展后刷新页面可恢复原界面；共享云端项目、旧副本、Codex 对话和单独安装的连接程序需分别处理。

详见 [共享云端预览方案](docs/shared-cloud-preview.md)、[Codex 本机连接](docs/codex-backend.md)、[架构与扩展方法](docs/architecture.md)、[Overleaf 接口依据](docs/overleaf-evidence.md)。本地 dev 页面明确标注“人工测试”，使用人工项目、真实 CodeMirror 和固定的 Codex 模拟回复，公式语法节点由测试适配模拟。它用于检查布局与交互，不能替代真实 Overleaf 页面和真实 Codex 问答的端到端验收。
