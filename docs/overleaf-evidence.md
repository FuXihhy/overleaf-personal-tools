# Overleaf integration evidence — 0.4.2

Read-only review on 2026-10-29, pinned to public Overleaf commit `e039ad26c5bf5422eb57b89fc7e57c75055e631d`. Public source does not establish the deployed overleaf.com version; these internal routes are not a stable extension API. Mock transport tests are not live acceptance. On 2026-10-29, a dedicated synthetic project verified clone creation, upload, compilation and PDF retrieval in Chrome. MathJax custom macros, native command completion and the registered local TeX host also passed live checks. These results do not establish compatibility with every project or later deployment.

## Read-only source and editor adapters

- [`router.mjs`](https://github.com/overleaf/overleaf/blob/e039ad26c5bf5422eb57b89fc7e57c75055e631d/services/web/app/src/router.mjs) exposes authorized ZIP and document `/download` routes. An endpoint without `/download` is not an interchangeable browser API.
- [`projectEntitiesJson`](https://github.com/overleaf/overleaf/blob/e039ad26c5bf5422eb57b89fc7e57c75055e631d/services/web/app/src/Features/Project/ProjectController.mjs#L523) returns paths/types, not file or root-folder IDs.
- [`editor/_meta.pug`](https://github.com/overleaf/overleaf/blob/e039ad26c5bf5422eb57b89fc7e57c75055e631d/services/web/app/views/project/editor/_meta.pug) and [`loadEditor`](https://github.com/overleaf/overleaf/blob/e039ad26c5bf5422eb57b89fc7e57c75055e631d/services/web/app/src/Features/Project/ProjectController.mjs#L708) provide project identity/name, not a full tree.
- [`MetaController`](https://github.com/overleaf/overleaf/blob/e039ad26c5bf5422eb57b89fc7e57c75055e631d/services/web/app/src/Features/Metadata/MetaController.mjs) returns LaTeX metadata such as labels/packages; it is not a folder-tree endpoint.
- [`IdeProvider`](https://github.com/overleaf/overleaf/blob/e039ad26c5bf5422eb57b89fc7e57c75055e631d/services/web/frontend/js/shared/context/ide-context.tsx) exposes an unstable editor store. Feature-detect it and overlay buffers only when their full paths are unambiguous.

The source adapter reads a bounded ZIP and retains decoded text in tab memory. The compressed archive includes other assets, but binary entries are not inflated into the text snapshot. Manual refresh updates the snapshot; typing uses confirmed editor overlays.

The ZIP does not identify the selected main file authoritatively. After the ZIP succeeds, `project-metadata.ts` makes one short, same-origin, authenticated project-metadata connection. [`ProjectEditorHandler.buildProjectModelView`](https://github.com/overleaf/overleaf/blob/e039ad26c5bf5422eb57b89fc7e57c75055e631d/services/web/app/src/Features/Project/ProjectEditorHandler.mjs#L14) includes the selected `rootDoc_id` and `rootFolder`; its document entries contain `_id` and `name`, without document text. The adapter maps the root ID through that bounded tree to a full project path and immediately disconnects. It emits no application event and never joins a document, changes settings, or touches the website's existing socket. The server can still record normal project join/leave presence activity.

Explicit extension selection wins, followed by an already-present `select#rootDocId` choice, this authoritative project root, and a unique uncommented `\documentclass` candidate. The adapter never guesses `main.tex`. Metadata failure or an unmatched archive path falls back without blocking indexing; it does not trigger repeated retries. Metadata is cached with the ZIP until explicit refresh. A capture-phase change listener records the native selection synchronously; this observed value takes precedence over transient controlled-select DOM values until the next selection or refresh. A revision guard prevents older metadata from replacing a newer selection. The connection times out after six seconds and is cancelled if that snapshot is invalidated. Source tests use only synthetic metadata and archives. On 2026-10-29 the deployed website correctly supplied the selected main document for a dedicated synthetic project with two document-class candidates, without opening its native Compiler panel; this is not a compatibility guarantee for every deployment.

## Preview lifecycle and typography

### Independent popup in 0.6.0

The pinned [`extensions/bundle.ts`](https://github.com/overleaf/overleaf/blob/e039ad26c5bf5422eb57b89fc7e57c75055e631d/services/web/frontend/js/features/source-editor/extensions/bundle.ts) exports the host ViewPlugin/EditorView interfaces but not the native math-preview StateField or the caret-tooltip facet. The extension therefore uses its own portal and host `requestMeasure` coordinates, rather than reaching into native private state. Formula identity and geometry are separate events; no native MathJax node is used as a result or fallback.

After reloading 0.6.0 on 2026-10-30, a live synthetic project with native Equation preview switched off still showed the extension's formula popup. In `x^2 + \\bRsdfsdfsdf + \\frac{1}{2}`, only the unknown command was red, with both the power and fraction retained. There were no native tooltip nodes. The original native setting and synthetic source were restored after this check. The fixture also typed 15 characters continuously: 100 sampled frames contained no status/error banner and no visible native preview; the final SVG retained the red command and fraction. These are scoped checks, not a claim about all browsers or formula sizes.

The existing cloud copy also verified the new TeX flow: a current-formula SVG draft appeared immediately, followed by a PNG with `data-opt-render-kind="tex"` after the cloud result completed. No loading text appeared, and native containers remained hidden. The synthetic project was returned to MathJax afterwards. Release verification passed 298 automated tests, including actual content/popup event integration and stale-request/cooldown cases.

### Previous 0.5.0 integration evidence

On 2026-10-30, read-only live DOM inspection confirmed that the editor uses the Noto Sans interface family, while `.cm-completionDetail` deliberately uses a larger STIX Two Math font for native math details. Extension source labels therefore opt into scoped interface typography rather than inheriting that math-detail rule.

The pinned [`math-preview.ts`](https://github.com/overleaf/overleaf/blob/e039ad26c5bf5422eb57b89fc7e57c75055e631d/services/web/frontend/js/features/source-editor/extensions/math-preview.ts) creates an opacity-zero wrapper containing the raw formula, asynchronously replaces it with MathJax SVG, then reveals it and requests repositioning. The 0.5 adapter witnesses that raw formula for native fallback and claims the equation body during pending renders. Browser fixture checks on 2026-10-30 exercised delayed native writes at 45 and 240 ms: extension success and dual failure each showed zero native-error frames across 90 sampled frames; a valid same-formula native result appeared only after extension failure. These fixture observations do not substitute for a newly reloaded live extension check.

After the user reloaded 0.5.0 on 2026-10-30, the existing synthetic Overleaf project verified nested `ensuremath` plus custom commands, physics, source disable/reset, and the existing cloud copy's single-formula PDF preview. The original native wrapper stayed hidden during pending and successful renders; after disabling the macro file, its red undefined-command SVG remained hidden rather than being accepted as a valid fallback. Completion source labels and failure text computed to Noto Sans, 12px, centered. Both English and Chinese native Settings panels exposed the new controls. Live checks used artificial text only and did not edit the user's working research project or create another cloud copy. Frame-level counts above remain fixture measurements; live DOM checks do not claim every animation frame was recorded.

## Interface language and exact site scope

[`layout-base.pug`](https://github.com/overleaf/overleaf/blob/e039ad26c5bf5422eb57b89fc7e57c75055e631d/services/web/app/views/layout-base.pug) exposes the chosen interface locale as `meta[name="ol-i18n"]` JSON field `currentLangCode` and the HTML `lang` attribute. The native [`i18n.ts`](https://github.com/overleaf/overleaf/blob/e039ad26c5bf5422eb57b89fc7e57c75055e631d/services/web/frontend/js/i18n.ts) initializes directly from that meta value. [`Translations.mjs`](https://github.com/overleaf/overleaf/blob/e039ad26c5bf5422eb57b89fc7e57c75055e631d/services/web/app/src/infrastructure/Translations.mjs) maps the request host to the locale; browser language only supplies a suggested-language banner. Chinese uses `zh-CN`. The editor's separate `ol-languages` meta is a spelling-dictionary list, not its interface locale.

The native [`LanguagePicker`](https://github.com/overleaf/overleaf/blob/e039ad26c5bf5422eb57b89fc7e57c75055e631d/services/web/frontend/js/shared/components/language-picker.tsx) navigates to a language site's URL plus the current path. Read-only live DOM inspection on 2026-10-29 confirmed `ol-footer.subdomainLang.cn = {lngCode:"zh-CN",url:"https://cn.overleaf.com"}` and the English entry `https://www.overleaf.com`. The extension therefore permits only those two exact HTTPS origins in its manifest, native sender guard, and metadata/cloud transports. `overleaf/origin.ts` shares that allowlist. A page on one permitted origin still cannot request the other's authenticated session; nonstandard ports, other language subdomains, and lookalike hosts remain rejected. No wildcard subdomain permission was added.

## Clone creation and environment

[`router.mjs`](https://github.com/overleaf/overleaf/blob/e039ad26c5bf5422eb57b89fc7e57c75055e631d/services/web/app/src/router.mjs#L755) routes `POST /project/{sourceId}/clone` through project read authorization. [`cloneProject`](https://github.com/overleaf/overleaf/blob/e039ad26c5bf5422eb57b89fc7e57c75055e631d/services/web/app/src/Features/Project/ProjectController.mjs#L394) accepts `projectName` and returns `project_id`, name and owner metadata, without a root-folder ID. This creates a real account project, not an ephemeral compile job.

[`ProjectDuplicator`](https://github.com/overleaf/overleaf/blob/e039ad26c5bf5422eb57b89fc7e57c75055e631d/services/web/app/src/Features/Project/ProjectDuplicator.mjs) flushes source docs, copies document/file blobs and the directory tree, carries over the compiler and sets the copied root. Binary assets survive the initial clone. It creates a blank project with its default image and does not promise the original TeX Live image; cache preparation explicitly handles differing images.

The extension calls clone only after the native-settings button is pressed. All later upserts/settings/compiles target the stored copy. Files persist there. The source may acquire Overleaf's normal clone audit/activity effects, but its document contents and compilation settings are not edited by the extension.

[`updateProjectSettings`](https://github.com/overleaf/overleaf/blob/e039ad26c5bf5422eb57b89fc7e57c75055e631d/services/web/app/src/Features/Project/ProjectController.mjs#L202) accepts `compiler` and `imageName` at `/project/{id}/settings`. `rootDocId` on this endpoint changes the main file persistently and is deliberately not sent. Environment synchronization is attempted only from available native controls; otherwise the copy must be checked by the user. Equal compiler names do not establish equal TeX Live/packages.

## Clone root folder

[`EditorRouter`](https://github.com/overleaf/overleaf/blob/e039ad26c5bf5422eb57b89fc7e57c75055e631d/services/web/app/src/Features/Editor/EditorRouter.mjs) registers HTTP project join on its private API router with private authentication. It must not be used as an ordinary browser endpoint or as a reason to seek private credentials.

Real-time connections include `projectId` in their query. The server automatically joins that project and emits `joinProjectResponse` with its tree; see [`Router.js`](https://github.com/overleaf/overleaf/blob/e039ad26c5bf5422eb57b89fc7e57c75055e631d/services/real-time/app/js/Router.js#L703) and the official [`RealTimeClient` helper](https://github.com/overleaf/overleaf/blob/e039ad26c5bf5422eb57b89fc7e57c75055e631d/services/real-time/test/acceptance/js/helpers/RealTimeClient.js#L63). [`WebsocketController`](https://github.com/overleaf/overleaf/blob/e039ad26c5bf5422eb57b89fc7e57c75055e631d/services/real-time/app/js/WebsocketController.js) runs normal join/leave handling.

The extension bundles the official [`socket.io-client` tag `0.9.17-overleaf-6`](https://github.com/overleaf/socket.io-client/tree/0.9.17-overleaf-6), matching the public service dependency. Modern socket.io is not a protocol substitute. A forced-new connection to the clone reads `project.rootFolder[0]._id` then disconnects. It does not reuse the source socket, join a document or send edits. Joining can still update normal activity/presence state.

## Upload contract and persistence

The native [`batch-file-uploader`](https://github.com/overleaf/overleaf/blob/e039ad26c5bf5422eb57b89fc7e57c75055e631d/services/web/frontend/js/infrastructure/batch-file-uploader.ts) posts `/project/{id}/upload?folder_id={id}` with FormData `qqfile`, `name`, optional `relativePath`, and `X-CSRF-TOKEN`. [`uploadFile`](https://github.com/overleaf/overleaf/blob/e039ad26c5bf5422eb57b89fc7e57c75055e631d/services/web/app/src/Features/Uploads/ProjectUploadController.mjs#L131) returns `{success, entity_id, entity_type, hash}`. The uploaded TeX document's `entity_id` supplies `rootDoc_id` for compilation.

[`FileSystemImportManager`](https://github.com/overleaf/overleaf/blob/e039ad26c5bf5422eb57b89fc7e57c75055e631d/services/web/app/src/Features/Uploads/FileSystemImportManager.mjs#L22) uses replacement/upsert behavior. [`upsertDoc`](https://github.com/overleaf/overleaf/blob/e039ad26c5bf5422eb57b89fc7e57c75055e631d/services/web/app/src/Features/Project/ProjectEntityUpdateHandler.mjs#L387) resolves the supplied folder ID through [`ProjectLocator`](https://github.com/overleaf/overleaf/blob/e039ad26c5bf5422eb57b89fc7e57c75055e631d/services/web/app/src/Features/Project/ProjectLocator.mjs#L26). This path does not make an omitted folder ID default to the root.

An upload overwrites the corresponding clone file. Text synchronization neither copies changed binaries nor deletes old paths. A fresh clone is required for asset changes and source removals/renames; refreshing source ZIP alone does not reconcile stale clone entries.

## Compilation and output

The native [`math-preview.ts`](https://github.com/overleaf/overleaf/blob/e039ad26c5bf5422eb57b89fc7e57c75055e631d/services/web/frontend/js/features/source-editor/extensions/math-preview.ts) calls `repositionAllTooltips()` after asynchronous rendering. [`tooltips-reposition.ts`](https://github.com/overleaf/overleaf/blob/e039ad26c5bf5422eb57b89fc7e57c75055e631d/services/web/frontend/js/features/source-editor/extensions/tooltips-reposition.ts) handles the `editor:repositionAllTooltips` window event with the host's own CodeMirror `repositionTooltips(view)`. The extension forwards its `opt:measure` notification through this existing event. A plain `view.requestMeasure()` does not reliably schedule tooltip positioning. Further live investigation showed that native `above:true` / `strictSide:true` placement also deliberately hides a formula near the editor’s top edge. Version 0.3.0 adds a narrowly scoped fallback after native measurement: it requires one active editor, one managed popup matching the exact current formula, a visible formula anchor, insufficient room above and sufficient room below. It repositions the same body-portaled popup below that anchor and restores native styles on selection, scroll, disable or teardown; offscreen anchors remain hidden. Further live tests found that observer-driven recovery could repeatedly compete with native placement. Version 0.4.1 instead uses a narrowly scoped CSS variable override only while the verified fallback marker is present. Native inline coordinates remain untouched; no style observer or repeated recovery measurement is used. Selection, scrolling, resizing, disabling and teardown remove the marker and variables so native placement resumes. Version 0.4.2 also handles native absolute-positioned portals with no usable offsetParent: it checks ancestor containing blocks and uses fixed viewport placement only for the verified fallback. Transformed or contained ancestors are not guessed through.

Ordinary [`CompileController`](https://github.com/overleaf/overleaf/blob/e039ad26c5bf5422eb57b89fc7e57c75055e631d/services/web/app/src/Features/Compile/CompileController.mjs) requests contain options, not arbitrary source/resources; content comes from actual project files. The private submission route seen in tests does not establish a session-accessible virtual-source API.

Native [`compiler.ts`](https://github.com/overleaf/overleaf/blob/e039ad26c5bf5422eb57b89fc7e57c75055e631d/services/web/frontend/js/features/pdf-preview/util/compiler.ts#L137) sends both `rootDoc_id` and `rootResourcePath`. [`CompileManager`](https://github.com/overleaf/overleaf/blob/e039ad26c5bf5422eb57b89fc7e57c75055e631d/services/web/app/src/Features/Compile/CompileManager.mjs) fills the project root when the path is absent; [`ClsiManager`](https://github.com/overleaf/overleaf/blob/e039ad26c5bf5422eb57b89fc7e57c75055e631d/services/web/app/src/Features/Compile/ClsiManager.mjs#L1115) resolves IDs during resource construction. Sending both fields follows the native one-off override and prevents accidental fallback. It does not itself persist a new main-document setting.

A one-off root override still shares that project/user's compile workspace, caches and outputs. It could interfere with original-project compilation, hence the dedicated clone. The request schema accepts `compiler`, but the inspected final CLSI request uses `project.compiler`; the extension updates the clone's setting rather than relying on the body option.

The ordinary compile HTTP request waits for a result; it does not return an async ticket for polling. Status, output/build identifiers and routing metadata are described in [`types/compile.ts`](https://github.com/overleaf/overleaf/blob/e039ad26c5bf5422eb57b89fc7e57c75055e631d/services/web/types/compile.ts). Busy, too-recent and backoff conditions remain visible; the extension does not automatically retry mutations.

[`output-files.ts`](https://github.com/overleaf/overleaf/blob/e039ad26c5bf5422eb57b89fc7e57c75055e631d/services/web/frontend/js/features/pdf-preview/util/output-files.ts) builds `/download/project/{id}/build/{build}/output/output.pdf` with `editorId` and optional `clsiserverid`; authorized routes appear in [`router.mjs`](https://github.com/overleaf/overleaf/blob/e039ad26c5bf5422eb57b89fc7e57c75055e631d/services/web/app/src/router.mjs#L646). The client uses this same-origin build-specific path and the build log route, not arbitrary returned hosts. The compiler returns PDF rather than dedicated formula SVG; bundled PDF.js makes the popup image.

Validate with explicit clone creation in a disposable project. Preserve the rule that only the newly created bound copy receives uploads/settings/compiles. Public-source matching and mock requests support the implementation design, not a claim of a successful production session.

## Extension lifetime acceptance, 2026-10-30 (0.6.2)

The reported `Extension context invalidated` stack maps to the native settings panel's direct `chrome.runtime.getURL` call for its avatar when a new settings dialog appears. A content script surviving an extension reload can still observe DOM changes while its Chrome API context is no longer usable. The shared context guard now retires that instance and its UI without polling or keeping the background service worker alive.

The final local Chrome harness rendered the partial-error formula normally, then its explicit test control invalidated only the fixture's synthetic runtime. It reported zero extension tabs, zero preview popups, no remaining native-preview suppression and zero uncaught errors. Reopening and closing Settings retained the native Editor/Project controls without remounting the retired extension. The screenshot is `artifacts/0.6.2/context-retired.png`. This simulates context loss in a real browser; it does not claim the installed extension has already been reloaded or tested on the live Overleaf site.

TypeScript, build and all 342 tests passed. New regressions cover invalid runtime getters/resource URLs, pending settings actions and discovery, delayed render results and native-message callbacks, plus cloud metadata/socket/queued upload/compile/output-download boundaries. In-flight network requests may finish; a retired instance cannot initiate the next operation. No cloud project was created, migrated or removed during this fix. Chrome's ordinary idle service-worker shutdown is distinct from a content-script context invalidation.

## Shared workspace acceptance, 2026-10-30 (0.7.0)

The cloud implementation now creates a basic account workspace via `POST /project/new` with `template: 'none'`, rather than calling clone. The official [ProjectController](https://github.com/overleaf/overleaf/blob/main/services/web/app/src/Features/Project/ProjectController.mjs) returns the new project and its owner; [ProjectCreationHandler](https://github.com/overleaf/overleaf/blob/main/services/web/app/src/Features/Project/ProjectCreationHandler.mjs) initializes a basic `main.tex`. [layout-base.pug](https://github.com/overleaf/overleaf/blob/main/services/web/app/views/layout-base.pug) supplies the current `ol-user_id`, and verified project metadata supplies compiler/imageName and the owner. Cleanup uses the official [EditorRouter](https://github.com/overleaf/overleaf/blob/main/services/web/app/src/Features/Editor/EditorRouter.mjs) doc/file DELETE routes, limited to the recorded matching path, ID and type. The historical clone sections above describe older releases, not the current implementation.

After the user reloaded 0.7.0, live English-site verification created one `Overleaf Personal Tools — Preview` project. Repeating the connection action retained the same project ID. Two existing formulas in the current source project completed real cloud TeX rendering; the visible popup's DOM identified the current result as `tex`, with the corresponding formula key. Selecting the second formula first showed an immediate `draft`, then its own TeX result. Leaving and re-entering the first formula returned the cached TeX popup within 187 ms measured around the automated caret actions and DOM wait; this includes automation overhead and is not a TeX compiler timing. A later second-formula observation spanned separate tool calls and is not used as a latency measurement.

A second existing project on the Chinese site automatically displayed the identical shared project ID without a create action. The account project list showed exactly one match for the new shared-workspace name. These checks did not edit source document contents or create full project copies. The first project's original MathJax engine setting was restored after verification; the second project's engine selection was never saved. The shared binding remains available for future cloud previews. Screenshots are saved under ignored `artifacts/0.7.0/` (`live-cloud-preview.png`, `live-reuse-cn.png`, and local bilingual settings screenshots). Live simultaneous compilation from both source projects was not exercised; cross-project transaction serialization is covered by the integration tests.

TypeScript, build and all 406 automated tests passed. Two integration tests use the real coordinator client/background broker with two preview services across www/cn senders: synchronization through PDF delivery is exclusive, dependencies are replaced only after release, and obsolete queued formulas do not read or mutate cloud state. Other new tests cover account isolation, creation certainty, restarts, lock fencing, dirty synchronization journals, unknown files, dependency closure, environment changes, cache hits and bilingual diagnostics. No extension permission was added.
