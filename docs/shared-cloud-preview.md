# 共享云端公式预览

云端 TeX 使用一个由扩展管理的轻量项目，所有论文项目轮流复用它。它是一处临时编译工作区：每次放入当前公式需要的导言区和文本依赖，生成一页 PDF，再将结果显示在原编辑器的公式弹窗里。它不再为每篇论文复制整个项目。

## 第一次启用，以及以后如何使用

在原有 **Settings → Extension** 中选择 **TeX → Overleaf**，首次启用共享云端预览项目。扩展创建名为 **Overleaf Personal Tools — Preview** 的空白项目，并保存其绑定。以后在其他论文项目中选用云端模式，会使用同一个绑定；重复点击启用也只验证和连接已有项目。

“共用一个”的范围是**同一 Chrome 用户配置中的同一 Overleaf 账号**。英文站和中文站共享这个绑定，不因切换界面语言重复创建。账号以 Overleaf 页面提供的用户 ID 区分，不以邮箱、显示名或项目名称区分。另一台电脑或另一个 Chrome 用户配置没有这份扩展存储，目前不会自动找到同一个预览项目。

旧版本创建的逐论文副本保留，扩展不会自动把其中一个改作共享工作区，也不会自动删除它们。新共享模式启用后，旧副本不再参与新的预览流程。需要清理旧副本时，可以在确认没有其他用途后自行处理。

## 一个公式实际带走哪些内容

TeX 不能普遍只接收一段公式字符串就完成排版：公式可能用到了导言区中的宏包选项、命令定义和字体设置。因此，生成文档由三部分构成：

1. 当前主文件中能明确识别的完整导言区，即 `\begin{document}` 之前的内容。
2. 按设置补入的额外定义文件，以及这些内容实际引用的项目文本依赖。
3. 当前选中的公式，放在 `preview` 宏包环境中，用于得到紧凑的一页输出。

原主文件的正文不会上传到这个共享项目。无关章节、未引用的 bibliography 和未使用的样式文件也不会因为它们存在于项目目录中就被复制。扩展仍先通过既有同源 ZIP 读取方式获取项目快照；这次优化的是**上传到预览项目的内容**，并不表示读取源项目的网络请求已经变成逐文件下载。

依赖收集会跟踪明确写出的 `\input`、`\include`、本地 `\usepackage` / `\RequirePackage`、文档类加载和 import 链。例如，`main.tex` 使用 `custom.cls`，文档类再加载 `layout.sty`，而样式文件又输入 `defs/operators.tex`，这些文本会一起进入预览工作区。TeX Live 已安装的 `physics`、`amsmath` 等宏包直接由 Overleaf 提供，不需要扩展下载或上传。

用户的额外文件设置继续有效：默认寻找唯一的 `macros.sty`，没有就不额外添加，也可改文件名、手动选择或关闭。预览来源开关和顺序仍按各论文项目独立保存。它们只改变生成的预览文本；真实 TeX 仍遵守 `\newcommand`、`\renewcommand` 等声明的原有语义，不会为了表现“优先级”而改写成另一种定义方式。

## 如何避免共享项目越来越大，或混用两篇论文的定义

共享工作区保留**当前任务需要的文件集合**，不为每篇论文再保存一套目录。例如，论文 A 和 B 都有 `macros.sty`，切到 B 时会用 B 的内容更新这个路径，并删除只有 A 需要、由扩展登记的旧文件。各项目不会因为文件名相同而共用宏定义。

扩展为每个已上传文件记录内容摘要。摘要是从内容计算出的指纹；相同内容会得到相同摘要，用于判断是否需要再次上传。只改公式而导言区和依赖没有变化时，通常只需要更新生成入口。这里节省的是文件同步工作，Overleaf 的真实 TeX 编译仍然需要运行。

上传之前登记待写路径，完成后保存文件 ID、类型和摘要。即使公式在上传途中发生变化，也先完成这一步登记，之后才能安全清理。下次任务会与共享项目的目录核对：只有身份匹配的已登记文件可以由扩展清理；发现陌生文件或文件身份被替换会停止同步并说明原因。

因此，共享项目应专供扩展使用，不适合手动写论文或存放其他文件。目录身份检查不能发现所有“保留同一文件 ID 的原地手动改写”，不要把它当作能自动合并人工编辑的文稿。

## 同时打开多个项目时会怎样

一个账号的同步、编译和 PDF 获取作为一个完整任务排队。任务 A 持有工作区期间，任务 B 可以继续显示本地的 MathJax 草稿，但不能覆盖 A 正在编译的文件。A 的结果获取完毕，或确认没有正在等待的网络操作后，才交给下一个仍然有效的任务。

例如，A 先同步自己的宏文件并开始编译，B 随后请求另一条公式：B 等待；A 下载属于这次构建的 PDF 后释放工作区；B 再换入自己的依赖和编译环境。返回结果带有公式和版本检查，A 的迟到结果不会显示在 B 的公式上。

队列按请求先后分配工作区，但不会把每次按键都变成必须完成的编译。等待期间公式已经变化的请求会退出，页面只为最新公式继续安排任务。已经送达服务器的编译可能仍会运行到结束；扩展会丢弃过时结果，而不是通过立即覆盖文件来“取消”它。

为应对标签页关闭、扩展更新或网络请求结果不明确，工作区锁采用短期租约：有效期为 30 秒，只在任务占用期间每 10 秒续约，并在实际网络操作前检查持有者身份。空闲页面没有这个心跳。失联后额外保留 300 秒隔离期，让可能仍在服务器执行的旧请求有时间结束；从最后一次续约算起，异常等待可能接近 5 分半。正常任务结束会立即释放，不需要等这个隔离期。

锁身份和期限保存在本地扩展存储中，服务进程休眠或浏览器重启不会立刻把正在使用的工作区交给另一个页面。这种异常等待是为了避免两次文件同步交叉，不是正常预览都要等几分钟。

## 如何保持输入流畅

键入时先显示当前公式的 MathJax 草稿，不显示反复跳动的“正在渲染”横幅。停顿 **650 毫秒** 后才安排云端 TeX；恢复输入会使旧请求失效。草稿和真实 TeX 结果可能因字体、宏包实现而有差异，草稿的悬停说明会标明它的性质。

流畅度主要靠减少无效工作，而不是假定云端编译非常快：

- 相同依赖按摘要跳过上传，只同步变化内容。
- 页面内缓存最多 **12 份、合计 16 MiB** 的 TeX PDF；公式、依赖和编译环境都一致时复用结果。
- 同账号云端编译间隔至少 **3 秒**；已尝试的云端请求失败后通常退避 **10 秒**，避免连续输入变成请求风暴。
- 多标签页排队时保留即时草稿，过时请求退出，结果只更新对应的当前公式。

这仍然是云端 TeX：网络延迟、项目的导言区复杂度、Overleaf 排队和账号编译限制都影响耗时。650 毫秒是输入停顿阈值，不是编译完成时间；缓存命中也不代表所有首次预览都同样快。

## 编译器、版本和原项目

每次需要新编译时，会读取原项目的编译器和 TeX Live 镜像信息；元数据短期缓存 15 秒，当前页面修改原生编译器或版本设置时立即使缓存失效。随后在排队任务内部将共享项目匹配到该环境。读不到明确值时停止并提示，避免默默按默认 pdfLaTeX 编译。

扩展只改变共享项目的编译设置和文件。原项目的源文稿、主文件和编译器设置保持原样。它借用 Overleaf 当前登录会话，编译仍消耗该账号资源。

匹配编译器与 TeX Live 也不等于复现整篇文章的运行状态。正文前面才定义的命令、标签和交叉引用、计数器、辅助文件、`\jobname`、外部工具和复杂输出钩子可能不同。预览目标是独立执行当前公式，不是截取原 PDF 中已排版的那一段。

## 仍然存在的限制与数据保留

依赖收集不是完整的 TeX 解释器。明确的字面量路径可以递归跟踪；用宏拼接出的文件名、特殊 catcode 或动态加载流程无法普遍静态判定。这些情况会尽可能给出诊断，可以把需要的文本明确加入额外文件；不会为了解决不确定性而悄悄重新复制整个论文项目。

本轮轻量模式只同步文本，不同步项目图片、PDF 或字体二进制。可识别的实际资源加载会直接说明限制；宏定义或不确定条件内部的资源加载可能先给诊断，执行时仍会失败。使用 TeX Live/系统已安装字体与使用项目自带字体是不同情形。MathJax 的能力限制也不会因选择云端而消失：它仍只是等待 TeX 结果时的即时草稿。

共享项目在 Overleaf 列表中是一个真实项目，生成入口和依赖会持久保留。后续清理旧文件不保证从 Overleaf 历史记录中彻底移除旧文本。扩展本地存储只保留设置、绑定、文件身份/摘要和排队期限；文稿快照、公式和 PDF 缓存留在页面内存，不作为扩展存储内容保存。

创建请求若有明确返回的项目 ID，会保留绑定以便后续恢复；若网络中断导致创建结果未知，会停止并让用户检查项目列表，避免重复点一次就多建一个项目。原有副本也不会在升级中自动删除。

## 后续功能如何继续维护

文档组装、云端请求、共享队列、界面展示分别由独立模块负责：`cloud-document.ts` 生成单公式依赖包；`cloud-client.ts` 管理 Overleaf 接口和写入边界；`cloud-coordinator.ts` 及后台协调器管理账号队列与租约；`tex-service.ts` 组合文件同步、环境和缓存；`content.ts` 只把当前编辑状态连接到预览 UI。

以后增加二进制依赖、其他编译服务或更完善的缓存，可以扩展对应模块，而不把这些逻辑塞进设置界面或公式弹窗。源码中的自动测试检查依赖裁剪、并发、失效恢复和权限边界；真实 Overleaf 接口的验收需要单独记录。旧版复制项目流程的线上成功，不能替代共享模式的线上验证。
